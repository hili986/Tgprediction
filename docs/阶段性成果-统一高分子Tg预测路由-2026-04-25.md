# 阶段性成果：统一高分子 Tg 预测路由与共聚物统计预测方法

日期：2026-04-25

课题方向：共聚物 Tg 的统计预测方法研究——从虚拟数据增强到 DNA 跨域拓展

## 1. 阶段目标

本阶段目标是把前期分散的 Tg 预测能力整理为一个可复用的统一预测入口，覆盖三类任务：

1. 均聚物 Tg 预测。
2. 一般二元/多元/嵌段共聚物 Tg 预测。
3. 核酸/碱基功能化共聚物 Tg 跨域预测。

同时，本阶段重点解决了两个实际问题：

1. 旧预测脚本在生成虚拟共聚物数据时存在“每条样本重复加载模型”的低效问题。
2. 共聚物数据中存在同一体系、同一组成下 Tg 严重冲突的脏数据，会显著压低模型上限。

当前已经形成一个统一路由脚本：

```bash
scripts/predict_polymer_tg_universal.py
```

该脚本按输入类型和可用证据自动分发到不同预测路线。昂贵的 BestTg/TabPFN 模型采用懒加载策略：只有在路线真正需要时才加载，并且在同一进程中只加载一次。

## 2. 当前方法总览

### 2.1 均聚物路线：BestTg / 186d TabPFN

均聚物采用当前项目中最强的均聚物 Tg 预测方法：

```text
PHY-C-light 58d + GNN embedding 64d + polyBERT PCA 64d = 186d
模型：TabPFNRegressor
```

对应脚本：

```bash
scripts/predict_tg_tabpfn_186d.py
```

统一路由脚本中，当输入为单个 repeat-unit SMILES 时，自动进入该路线：

```bash
python scripts/predict_polymer_tg_universal.py \
  --smiles '*CC*' \
  --device cuda
```

注意：统一路由正式推理时使用全量数据拟合的 BestTg 模型；阶段测试中的 heldout 指标是重新按 train/test split 做的严格评估，不等同于全量推理模型本身。

### 2.2 虚拟共聚物生成路线

虚拟共聚物生成仍基于 BestTg 的多组分近似预测能力：

```bash
scripts/generate_virtual_copolymer_dataset.py
```

其核心行为是：

1. 一个生成任务只创建一个 `BestTgPredictor` 实例。
2. `predictor.fit()` 只执行一次。
3. 后续所有 recipe 共用同一个模型对象。
4. 支持 `random`、`block`、`both` 架构扩展。
5. 支持二元和多元组成。

示例：

```bash
nohup python -u scripts/generate_virtual_copolymer_dataset.py \
  --mode auto \
  --auto-library bicerano \
  --output results/virtual_data/bicerano_binary_random_reuse.csv \
  --output-format csv \
  --device cuda \
  --architecture random \
  --min-components 2 \
  --max-components 2 \
  --weight-grid 0.2,0.5,0.8 \
  --chunk-size 100 \
  --resume \
  > logs/bicerano_binary_random_reuse.log 2>&1 &
```

### 2.3 一般共聚物路线：endpoint physics + calibration

一般共聚物的核心问题是：均聚物模型不能直接当成共聚物 Tg 模型。当前采用 endpoint physics + 校准的统计方法。

基础物理量：

```text
Tg1, Tg2: 两个均聚物端点 Tg
w1, w2: 共聚物组成
```

基础公式：

```text
Fox: 1/Tg = w1/Tg1 + w2/Tg2
```

当前脚本：

```bash
scripts/evaluate_polyinfo_copolymer_physics.py
scripts/evaluate_polyinfo_copolymer_advanced.py
scripts/filter_polyinfo_copolymer_conflicts.py
```

关键步骤：

1. 从 PoLyInfo 共聚物数据中解析二元共聚物体系。
2. 从 7k 去重均聚物数据库中查找两个端点 Tg。
3. 自动判断比例方向 `ratio_orientation`。
4. 对 mol% 行近似转换为 weight fraction。
5. 计算 Fox、Linear-Fox、Kwei、Physics-Ridge 等基线。
6. 对已知共聚物体系，使用同体系组成点做 residual IDW 校准。

### 2.4 冲突数据剔除

共聚物数据存在同一 `COID + w1_used` 下 Tg 冲突极大的情况。例如：

```text
P900016 EVA, w1=0.50, Tg -31 到 36 °C
P900016 EVA, w1=0.67, Tg -16 到 12.2 °C
P900017 EVOH, w1≈0.8697, Tg -24.8 到 61.6 °C
```

因此增加了冲突过滤脚本：

```bash
python scripts/filter_polyinfo_copolymer_conflicts.py
```

默认规则：

```text
同一 COID + 同一 w1_used 下，若 Tg 标准差 > 10 K，则整组剔除。
```

当前结果：

```text
原始 PoLyInfo 共聚物数据：223 行
clean 数据：212 行
剔除：11 行
冲突组：3 组
```

生成文件：

```bash
data/external/polyinfo_copolymer_tg_clean.csv
results/copolymer_residual_model/polyinfo_conflict_removed_rows.csv
results/copolymer_residual_model/polyinfo_conflict_filter_summary.json
```

### 2.5 核酸/碱基功能化共聚物路线

核酸共聚物目前采用专用策略，而不是直接套一般共聚物全局模型。

原因：

1. 核酸碱基功能化单体明显跨域，BestTg 的均聚物端点预测误差较大。
2. 核酸数据中已经有 A/T/C/G/nBA 端点 Tg，可以形成更强的实际端点物理校准。
3. 对核酸随机共聚物，实际端点 Linear-Fox / Physics-Ridge 明显优于通用模型端点。

相关脚本：

```bash
scripts/predict_nucleobase_excel_with_copolymer_model.py
scripts/evaluate_nucleobase_copolymer_strategies.py
```

## 3. 统一路由脚本

统一入口：

```bash
scripts/predict_polymer_tg_universal.py
```

### 3.1 路由规则

| 输入类型 | 默认路线 | 说明 |
|---|---|---|
| 单个 repeat-unit SMILES | BestTg 186d TabPFN | 均聚物正式预测路线 |
| 二元 random copolymer，匹配 clean PoLyInfo 已知体系 | Global Linear-Fox + same-system residual IDW | 已知体系内预测新组成 |
| 二元 random copolymer，未知体系但端点存在 | Global Linear-Fox | 新体系外推 |
| 多元 random copolymer | endpoint Fox | 当前为工程近似 |
| block copolymer | Fox miscible proxy + Tg window | 不假装处理真实相分离 |
| 端点不存在且允许 fallback | BestTg weighted descriptor/embedding mix | 探索性近似 |

### 3.2 单条均聚物预测

```bash
python scripts/predict_polymer_tg_universal.py \
  --smiles '*CC*' \
  --device cuda
```

### 3.3 单条二元共聚物预测

```bash
python scripts/predict_polymer_tg_universal.py \
  --smiles1 'CCCCOC(=O)C(C*)*' \
  --smiles2 '*C(C(=O)O)C*' \
  --w1 0.98 \
  --system-id P900001 \
  --device cpu \
  --no-besttg-fallback
```

如果给出 `--system-id` 且组件对匹配 clean calibration 表，则进入已知体系残差校准路线：

```text
router_route = binary_known_system_local_residual_idw
primary_method = global_linear_fox_plus_same_system_residual_idw
```

### 3.4 批量预测

输入 CSV 示例字段：

```csv
case_id,smiles1,smiles2,w1,COID,architecture,expected_tg_c
pba_paa,CCCCOC(=O)C(C*)*,*C(C(=O)O)C*,0.98,P900001,random,-42
```

运行：

```bash
python scripts/predict_polymer_tg_universal.py \
  --input-csv data/query.csv \
  --output results/predictions/universal_pred.csv \
  --device cuda
```

如果只想使用 endpoint/calibration，不想加载 BestTg 大模型：

```bash
python scripts/predict_polymer_tg_universal.py \
  --input-csv data/query.csv \
  --output results/predictions/universal_pred.csv \
  --device cpu \
  --no-besttg-fallback
```

## 4. 阶段测试结果

服务器测试目录：

```bash
results/universal_router_fulltest/
```

### 4.1 均聚物测试

测试文件：

```bash
results/universal_router_fulltest/homopolymer_holdout_summary.json
```

测试协议：

```text
train = 5988
test = 1498
PCA 只在 train 上拟合
TabPFN 只在 train 上训练
test 上评估
```

结果：

| 任务 | n_train | n_test | MAE/K | RMSE/K | R2 |
|---|---:|---:|---:|---:|---:|
| 均聚物 heldout | 5988 | 1498 | 20.60 | 34.48 | 0.907 |

解释：

这个 `R2=0.907` 是严格 heldout 结果。项目文档中记录的 `R2≈0.916/0.917` 来自更接近阶段最佳配置或 CV/全数据评估，两者评估协议不同，不能直接说模型退化。

### 4.2 一般共聚物测试

测试文件：

```bash
results/universal_router_fulltest/general_copolymer_universal_summary.json
```

clean PolyInfo 评估集：

```text
n_input = 149
n_predicted = 149
n_error = 0
```

统一路由重放结果：

```text
binary_known_system_local_residual_idw: 148
binary_global_linear_fox: 1
```

注意：统一路由重放会使用 calibration 表中已有行，因此生产重放指标接近完美，不作为论文泛化指标。应报告下列公平指标。

| 场景 | n | MAE/K | RMSE/K | R2 |
|---|---:|---:|---:|---:|
| 新体系外推：Linear-Fox leave-system-out | 149 | 16.49 | 23.61 | 0.820 |
| 已知体系：row-excluded residual IDW | 149 | 8.76 | 14.38 | 0.933 |
| 已知体系：leave-composition residual IDW | 149 | 11.28 | 15.79 | 0.920 |

结论：

1. 对完全没见过的新共聚物体系，目前较稳的泛化水平是 `R2≈0.82`。
2. 对已知共聚物体系内的新组成预测，清理冲突数据后可以达到 `R2≈0.93`。
3. 因此论文中必须明确区分“新体系外推”和“已知体系组成插值/校准”。

### 4.3 核酸共聚物测试

测试文件：

```bash
results/universal_router_fulltest/nucleobase_universal_summary.json
results/universal_router_fulltest/nucleobase_strategy_summary.json
```

核酸随机共聚物可评估样本：

```text
n = 17
```

统一脚本通用路由结果：

| 方法 | n | MAE/K | RMSE/K | R2 |
|---|---:|---:|---:|---:|
| 统一脚本 generic Linear-Fox | 17 | 10.63 | 13.14 | 0.564 |

核酸专用策略结果：

| 方法 | n | MAE/K | RMSE/K | R2 |
|---|---:|---:|---:|---:|
| BestTg/基础共聚物预测 | 17 | 13.16 | 18.16 | 0.167 |
| 实际端点 Linear-Fox leave-base-out | 17 | 4.28 | 5.62 | 0.920 |
| 实际端点 Physics-Ridge LOOCV | 17 | 2.93 | 3.41 | 0.971 |

结论：

1. 核酸共聚物不能只靠通用 PoLyInfo calibration。
2. 核酸体系必须接入实际端点 Tg 表，才能获得 `R2≈0.92` 的预测效果。
3. 下一步应把核酸实际端点策略加入统一路由脚本，形成 `nucleobase_known_endpoint` 专用 route。

## 5. 当前脚本说明

### 5.1 `scripts/predict_polymer_tg_universal.py`

用途：统一 Tg 预测入口。

核心特点：

1. 自动识别均聚物、二元共聚物、多元共聚物、嵌段共聚物。
2. 优先使用轻量 endpoint/calibration 路线。
3. 只有必要时才加载 BestTg 大模型。
4. 批量预测时一个进程只加载一次模型。
5. 输出 `router_route`、`primary_method`、`confidence`，便于追踪预测来源。

关键输出字段：

```text
tg_c_pred
tg_k_pred
router_route
primary_method
confidence
endpoint_tg_c
fox_endpoint_tg_c
global_linear_fox_tg_c
correction_c
```

### 5.2 `scripts/filter_polyinfo_copolymer_conflicts.py`

用途：生成 clean PoLyInfo 共聚物数据。

默认剔除规则：

```text
同一 COID + w1_used 的重复组成组，如果 Tg 标准差 > 10 K，则整组剔除。
```

运行：

```bash
python scripts/filter_polyinfo_copolymer_conflicts.py
```

输出：

```bash
data/external/polyinfo_copolymer_tg_clean.csv
results/copolymer_residual_model/polyinfo_conflict_removed_rows.csv
```

## 6. 当前可用于论文的表述

建议表述：

> 本研究构建了一个面向高分子 Tg 预测的分层路由框架。对于均聚物，采用 186 维多尺度特征与 TabPFN 模型；对于一般共聚物，采用端点 Tg 物理混合规则与数据驱动残差校准；对于核酸功能化共聚物，进一步引入实测端点 Tg 进行跨域校准。该框架能够根据输入体系自动分发到均聚物预测、一般共聚物外推、已知体系组成插值或核酸专用端点校准路线。

建议报告指标时分三类：

1. 均聚物 heldout：`R2=0.907, MAE=20.60 K`。
2. 一般共聚物新体系外推：`R2=0.820, MAE=16.49 K`。
3. 一般共聚物已知体系校准：`R2=0.933, MAE=8.76 K`。
4. 核酸共聚物专用端点策略：`R2=0.920, MAE=4.28 K`。

不建议把统一路由在 calibration 表上的重放指标作为论文主指标，因为它会使用同一体系已有数据，属于生产模式效果，不是严格泛化评估。

## 7. 下一步工作

1. 把核酸实际端点 Tg 表接入 `predict_polymer_tg_universal.py`，新增 `nucleobase_known_endpoint` 路由。
2. 对一般共聚物做更严格的外部数据验证，确认 `R2≈0.82` 的新体系外推能力。
3. 将虚拟共聚物数据预训练和 clean PoLyInfo 微调打通，形成统一训练脚本。
4. 对 block copolymer 增加多 Tg / phase separation 风险输出，而不是只给单一 Tg。
5. 将 `router_route` 和 `confidence` 纳入最终预测报告，避免不同可信度的预测混在一起。
